# 配置说明

配置只有一个 JSON 文件。找它的顺序是：

1. `--config <路径>`（命令行显式指定）
2. 环境变量 `ZBURN_CONFIG`
3. 当前目录的 `config.json`
4. `zburn.py` 所在目录的 `config.json`
5. `%LOCALAPPDATA%\zburn\config.json`

都没有才用内置默认值——内置默认值没有 agents、没有额度源，等于「能跑但不知道在给谁干活」。
`zburn doctor` / `zburn status` 第一行会打印这次实际读的是哪个文件，不会再让你猜。

默认值会被深合并，所以只写你要改的字段就行。

```jsonc
{
  "app": {
    "process_name": "ZCode",                    // 进程名（Get-Process -Name 用的那个）
    "exe": "E:\\exe\\Zcode\\ZCode.exe",         // 崩了要拉起的可执行文件
    "start_args": [],                           // 启动参数
    "strip_env": ["ELECTRON_RUN_AS_NODE"],      // 拉起前要清掉的环境变量（Electron 必填）
    "start_if_down": true                       // 是否自动拉起
  },
  "uia": {
    "send_button_regex": "发送|加入队列|立即|Send",
    "busy_regex": "停止生成|Stop generating",   // 出现它 = 正在输出
    "queued_regex": "移除待发送消息|Remove queued", // 出现它 = 已有排队消息
    "session_regex": "",                        // 会话名正则；空 = 只按 feed.targets
    "window_title_regex": "",                   // 多窗口时按标题选窗口；空 = 第一个主窗口
    "max_depth": 40,                            // 控件树遍历深度
    "char_delay_ms": 20,                        // 每字间隔（丢字就加大）
    "session_db": "",                           // ZCode 会话库；空 = ~/.zcode/cli/db/db.sqlite
    "session_work_dir": ""                      // 监督时优先取这个目录下最近的会话
  },
  "prompt": {
    "templates": ["Continue ...", "Keep going ..."],  // 轮换，避免每次同一句
    "file": "next-prompt.txt",                         // 当前指令落盘位置（人可读可改）
    "max_chars": 180                                   // 指令上限：WM_CHAR 打长了会丢字，0=不限
  },
  "feed": {
    "max_sessions": 5,                          // 一轮最多喂几个会话
    "interval_seconds": 120,                    // 巡检间隔
    "targets": [],                              // 精确会话名白名单（面板勾选生成）
    "rotate_after_turns": 3                     // 一个对话跑满几轮就换新的；0=不换
  },
  "model": {
    "want": "zcode2api",                        // 模型名里必须包含的字样（空=不校验）
    "auto_pin": true,                           // 发现不一致就尝试切回去（需要解锁桌面）
    "enforce": true,                            // 切不回去时这一轮不投喂，别把额度烧到别的模型
    "check_every": 10                           // 每 N 轮复检一次，防中途漂移
  },
  "gateway": {
    "health_url": "http://127.0.0.1:3000/meta",
    "start_command": "python -m uvicorn app.main:app --port 3000",
    "work_dir": "E:\\数据\\AI\\zcode2api",
    "grace_seconds": 60,                        // 探活失败先等 60 秒再判定真的挂了
    "keep_alive": true                          // 关掉就完全不碰网关
  },
  "quota": {
    "provider": "none",                         // none | gateway_zcode2api | command
    "url": "http://127.0.0.1:3000/admin/api/accounts",
    "admin_key": "",
    "refresh_url": "http://127.0.0.1:3000/admin/api/accounts/refresh",
    "refresh_body": { "all": true },
    "refresh_every_seconds": 600,
    "stop_below": 0,                            // 剩余 ≤ 它就收工；0 = 永不因额度停
    "command": ""                               // provider=command 时执行它
  },
  "paths": {
    "state_dir": ".zburn",                      // 日志/状态/心跳都在这
    "stop_file": "STOP",                        // 出现这个文件 run 就收工
    "bridge_dir": ""                            // 监督桥；空 = %LOCALAPPDATA%\zburn-bridge
  },
  "watchdog": {
    "heartbeat_stale_seconds": 420,             // 心跳超过它没更新 → 重启 run
    "check_seconds": 30
  },
  "agents": [                                   // 空 = 保持单应用行为
    { "id": "zcode", "name": "ZCode", "role": "worker", "enabled": true },
    { "id": "dsh", "name": "dsh", "role": "supervisor", "enabled": false,
      "supervises": "zcode",
      "app": { "process_name": "DeepSeek Harness",
               "exe": "E:\\exe\\DeepSeek Harness\\DeepSeek Harness.exe",
               "start_args": ["--force-renderer-accessibility"],
               "strip_env": ["ELECTRON_RUN_AS_NODE"] },
      "uia": { "send_button_regex": "发送|Send", "busy_regex": "停止|Stop",
               "queued_regex": "排队|Queue", "session_db": null },
      "feed": { "targets": ["zburn 监督"], "interval_seconds": 600, "max_sessions": 1 },
      "prompt": { "file": "supervisor-prompt.txt" } }
  ],
  "orchestrator": {
    "enabled": true,                            // 关掉 = supervisor 不再被唤醒
    "supervisor": "dsh",                        // agents 里的 id
    "worker": "zcode",
    "prompt": "",                               // 空 = 内置监督提示词
    "handoff_wait_seconds": 120                 // supervise --wait 的默认值
  },
  "new_chat": {
    "enabled": true,
    "button_regex": "新建任务|新建对话|新对话|New chat",
    "project": "",                              // ZCode 项目名；空 = 第一个新建按钮
    "send_button_regex": ""                     // 空 = 用 uia.send_button_regex
  }
}
```

## 常用改法

### 只喂指定的一两个对话（推荐）

面板「会话监控」卡 → 点「扫描侧栏对话」→ 勾上要监控的对话 → 「保存勾选」。
名单会常驻显示在卡片里，随时能单个移除。写进配置就是：

```json
"feed": { "targets": ["Supervisor: zburn", "我的项目"] },
"uia": { "session_regex": "" }
```

`targets` 里每条都是一个对话的标识，规则：

| 情况 | 存的样子 | 说明 |
|---|---|---|
| 侧栏里标题唯一 | `分析这个项目` | 去掉了末尾的相对时间（`刚刚 / 2分 / 49天`），手工抄带不带那段都能匹配 |
| 侧栏里有好几条同名 | `着色器预览#2` | `#N` 是同名组里从上往下的序号，只喂这一条 |
| 只写标题、不写序号 | `着色器预览` | 这一组同名对话全喂（手写配置时的宽松写法） |

UIA 不提供稳定的会话 ID（`AutomationId` 为空、`RuntimeId` 重启就变），所以身份就是
「标题 + 同名序号」。对话标题改了名就需要重新扫描勾选——匹配不上时**不会**退回全喂，
而是报「监控名单里的对话一个都没在侧栏找到 → 不投喂」。

它的优先级高于 `session_regex`。

### 不开面板，从命令行看/改名单

```powershell
python zburn.py sessions                 # 列出侧栏对话，标出 当前 / 名单内 / 匹配正则
python zburn.py target --match 着色器预览  # 把标题含这几个字的对话全部设为监控对象（替换名单）
python zburn.py target --add "完整标题"    # 追加一个
python zburn.py target --remove "完整标题"
python zburn.py target --clear            # 清空动态名单
```

`sessions` 里一个 `匹配正则` 都没有、名单又是空的，就是这个 agent 在**空转**：
它每 120 秒醒一次，什么都不喂。这是「跑了一夜额度没动」的最常见原因。

### 确认模型有没有钉住

```powershell
python zburn.py model                    # 读当前对话的模型，和 model.want 比对
python zburn.py model --set              # 不一致就切回去（要解锁桌面才能点下拉）
python zburn.py doctor                   # 每个配了 model.want 的 agent 各报一行
```

新建对话/轮换之后 zburn 会自动复查一次模型：不一致且桌面已解锁就自己切回去；
切不回去（锁屏）就记 `model_ok=false`，下一轮**不投喂**，等模型钉回来再继续。
宁可停一分钟，也不要把额度烧在别的模型上。

### 只喂我这个项目的会话（按正则）

```json
"uia": { "session_regex": "Supervisor:|着色器|完美世界" }
```

⚠️ **两个都为空就不投喂**（`feed_once` 直接返回「未指定监控对话」）。以前默认 `.`
等于「侧栏里每个对话都喂」，实测会把续派指令灌进所有会话——这是刻意改掉的。

### 加一个 supervisor（dsh）来验收 worker

`agents` 列表里写两个角色：`worker` 干活，`supervisor` 定时被唤醒。每一项只写差异字段，
会和顶层 `app/uia/feed/prompt` 深合并。完整机制见 [多Agent监督.md](多Agent监督.md)。

```json
"agents": [
  { "id": "zcode", "name": "ZCode", "role": "worker", "enabled": true },
  { "id": "dsh", "name": "dsh", "role": "supervisor", "enabled": true,
    "supervises": "zcode",
    "app": { "process_name": "DeepSeek Harness",
             "exe": "E:\\exe\\DeepSeek Harness\\DeepSeek Harness.exe",
             "start_args": ["--force-renderer-accessibility"] },
    "feed": { "targets": ["zburn 监督"], "interval_seconds": 600 } }
],
"orchestrator": { "enabled": true, "supervisor": "dsh", "worker": "zcode" }
```

三个关键点：

1. dsh 必须带 `--force-renderer-accessibility` 启动一次；
2. `dsh.feed.targets` 是 dsh 里专门做监督的那个对话标题（不是 ZCode 的）；
3. supervisor 的下一步必须是 ASCII（WM_CHAR 限制），中文只能出现在 `context.txt` 里。

### 新对话

```json
"new_chat": { "button_regex": "新建任务|新建对话|New chat", "project": "zburn" }
```

`project` 是 ZCode 侧栏里的项目名；不带项目时会点第一个「新建任务」按钮。
手动试：`python zburn.py newchat --config config.json --agent zcode --project zburn --prompt "Start a new task: ..." --dry-run`。

### 同一个客户端开了多个窗口

按窗口标题挑一个，避免把字打到另一个窗口里：

```json
"uia": { "window_title_regex": "zburn|我的项目" }
```

留空 = 第一个有主窗口的进程（旧行为）。

### 换个应用（以记事本举例）

```json
"app": { "process_name": "notepad", "exe": "C:\\Windows\\System32\\notepad.exe" },
"uia": {
  "send_button_regex": "Send",
  "busy_regex": "Stop",
  "queued_regex": "Cancel",
  "session_regex": "."
}
```

改之前先跑 `zburn.py probe --filter "Edit|Button"` 看控件长什么样。

### 用命令取额度（不接网关）

```json
"quota": {
  "provider": "command",
  "command": "curl -s https://api.example.com/balance",
  "stop_below": 500000
}
```

命令 stdout 里第一个 ≥4 位的整数会被当成剩余额度。

### 不想让它碰网关

```json
"gateway": { "keep_alive": false }
```

### 一轮多喂几个会话

```json
"feed": { "max_sessions": 5, "interval_seconds": 120 }
```

并行会话数受后端账号并发限制，超过会出现排队/429。实测 5 个是舒服的上限。

## 字段速查

| 字段 | 影响 |
|---|---|
| `feed.targets` | 精确会话名白名单，优先级最高；空 + 正则也空 = 不投喂 |
| `uia.session_regex` | 会话名正则；空 = 只按 `feed.targets` |
| `uia.window_title_regex` | 多窗口时按标题选窗口；空 = 第一个主窗口 |
| `uia.char_delay_ms` | 打字速度。小=快但可能丢字；20~25 稳 |
| `uia.max_depth` | 控件树太深会慢；40 够用 |
| `feed.max_sessions` | 一轮投喂上限（受后端并发限制） |
| `feed.interval_seconds` | 巡检周期。太小会反复空转，120 秒是经验值 |
| `feed.rotate_after_turns` | 一个对话跑满几轮就换新对话。不换 = 上下文平方级膨胀，白烧额度 |
| `prompt.max_chars` | 一条指令最多多少字符（WM_CHAR 打长了丢字）；`0` = 不限 |
| `model.want` | 模型名里必须包含的字样。新对话/轮换后自动复查，不对就切回去 |
| `model.auto_pin` | 不一致时是否自动切换（锁屏点不动下拉，只能等解锁） |
| `model.enforce` | 切不回去时是否跳过这一轮投喂（默认跳，避免烧错模型） |
| `model.check_every` | 每几轮复检一次模型，防中途被改 |
| `quota.stop_below` | 收工阈值 |
| `quota.refresh_every_seconds` | 主动刷新额度的间隔（有些后端要主动刷才更新） |
| `gateway.grace_seconds` | 探活失败后的冷静期，避免把"正在重启"误判成"挂了" |
| `watchdog.heartbeat_stale_seconds` | 守护进程被认为卡死的时间 |
| `paths.stop_file` | 手动收工开关（文件存在即停） |
| `paths.bridge_dir` | 监督桥目录；空 = `%LOCALAPPDATA%\zburn-bridge` |
| `agents` | 多 agent 列表；空 = 单应用（顶层 `app/uia/feed/prompt`） |
| `agents[].role` | `worker` 干活 / `supervisor` 定时验收 |
| `agents[].feed.interval_seconds` | 该 agent 自己的巡检周期（supervisor 默认 600 秒） |
| `agents[].enabled` | 面板「多 Agent」卡可单独启停 |
| `orchestrator.enabled` | 关掉后 supervisor 不再被唤醒（worker 仍可正常投喂） |
| `orchestrator.prompt` | 监督提示词模板；`{context}/{status}/{handoff}` 会替换成桥路径 |
| `new_chat.button_regex` | 新建对话按钮文案（不同客户端叫法不同） |
| `new_chat.project` | ZCode 项目名；空 = 第一个「新建任务」按钮 |
| `uia.session_db` | ZCode 会话库；空 = `~/.zcode/cli/db/db.sqlite`；`null` = 禁用 |
| `uia.session_work_dir` | supervisor 取会话时优先这个目录（避免抓到别的项目） |
