# 熄屏原理：锁屏下怎么把字送进应用

## 一、锁屏后能做什么、不能做什么

| 手段 | 锁屏下 | 原因 |
|---|---|---|
| `SetForegroundWindow` | ❌ 必然失败 | 会话切换/安全桌面隔离 |
| `SendKeys` | ☠️ **绝对不要用** | 焦点在锁屏密码框，字符会打进密码输入（真实事故风险） |
| 鼠标 `SetCursorPos + mouse_event` | ❌ 打偏 | 目标窗口不可见/不可激活 |
| **UI Automation 读控件树** | ✅ | UIA 由 COM 提供，不依赖前台；只要进程有窗口就能读 |
| **UIA `ValuePattern` / `InvokePattern`** | ✅ | 直接调用控件接口（`Invoke` 等于点按钮），不需要焦点 |
| **`PostMessage` + `WM_CHAR` 到目标窗口** | ✅ | 投递消息到目标线程的消息队列，与前台无关 |

结论：**读控件 + 调接口 + 投消息** 三件套在锁屏下都能用，这就是 zburn 的全部基础。

## 二、投喂一条指令的完整流程

```
1. 找窗口   : 进程名 → 有 MainWindowHandle 的那个 → AutomationElement.FromHandle
2. 找输入框 : 遍历控件树，取面积最大的 Edit（聊天输入框永远比搜索框大得多）
3. 找发送键 : 名字匹配 发送|加入队列|Send，且位置在输入框右侧/下方
              ⚠️ 必须排除 移除待发送消息|停止生成（它们名字里也含"发送/生成"）
4. 读现状   : ValuePattern.Current.Value（空输入框是 "\n"）
5. 打字     : PostMessage(hwnd, WM_CHAR, ch, 1)，每字 20~25ms，每 6 字停 80ms
6. 校验     : 再读一次内容，和期望字符串**逐字比对**
              · 少了 → 只补缺失后缀（不是从头重打，避免重复）
              · 是别人的内容 → 直接退出（exit 7），不追加
7. 提交     : InvokePattern.Invoke() 点「发送」；失败再兜底 PostMessage 回车
8. 确认     : 输入框内容变空 → 提交成功
```

## 三、五个必须知道的坑（都是实测）

### 1. WM_CHAR 太快会丢字
连续 PostMessage 每秒上千字符时，应用的事件队列会丢。实测 20~25ms/字稳定，每 6 字额外停 80ms。

### 2. 回车提交不稳定，按钮 Invoke 才可靠
`WM_KEYDOWN VK_RETURN` 有时进不了"提交"分支（应用可能在等 input 事件）。改成
`InvokePattern` 直接点发送按钮，一步到位；回车只作为兜底。

### 3. 「移除待发送消息」会被误判成发送按钮
这是本项目最危险的一个 bug：`发送` 正则同时命中
`移除待发送消息`（队列里的消息）和 `停止生成`（正在输出）。
如果按"最靠右"选，可能点到"移除待发送消息"——把队列里的指令删掉，还以为是发送成功。
**修复方式：选发送按钮时必须排除 queued/busy 的名字。**

### 4. 退格清不掉输入框（最反直觉）
实测结论（ZCode 2.x，2026-10）：

| 尝试 | 结果 |
|---|---|
| `WM_CHAR 0x08`（退格字符） | 无效，长度不变 |
| `WM_KEYDOWN/UP VK_BACK` | 无效 |
| `Ctrl+A` 后 `Backspace`（PostMessage 模拟修饰键） | 无效（修饰键状态不跨消息传递） |
| `ValuePattern.SetValue("")` | 无效（Chromium 忽略程序化置空） |

所以 zburn **不依赖清空**，而是：

- 输入框空 → 从头打；
- 输入框已是本指令的前缀（上次打一半失败） → 只补后缀；
- 输入框是别的残留 → 跳过（`exit 7`）并让人工清一次。

这个设计反而更安全：永远不会把新指令拼到别人的文本后面。

### 5. WM_CHAR 只认 ASCII
中文/日文会被应用侧映射成乱码。所以续派指令必须是英文（zburn 会自动过滤掉非 ASCII 字符）。

## 四、其它必须处理的现实问题

### 无障碍树会被关掉
Chromium 在长时间锁屏/窗口不可见时会把 accessibility tree 关掉，表现是：
控件树里只剩 `Intermediate D3D Window`，找不到输入框和按钮。
**唯一有效的恢复手段是重启应用**（重启后 tree 立刻恢复）。`zburn run` 检测到这种情况会自动重启。

### Electron 应用被环境变量污染会秒退
如果当前 shell/父进程带着 `ELECTRON_RUN_AS_NODE=1`，`ZCode.exe` 启动后会立即退出（退出码 0/9，
报 `bad option: --force-renderer-accessibility`）。所以拉起应用前要：

```powershell
Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
Start-Process -FilePath '...\ZCode.exe' -WindowStyle Minimized
```

### 网关只能探活，不能重启
重启正在服务的网关 = 所有对话断流（表现为 `connection lost mid-reply` / `turn.failed`）。
所以 `ensure-gateway.ps1` 只做「健康检查失败 → 启动」，绝不做 kill/restart。

### DPI 缩放
不同 DPI 下控件坐标不同，所以 zburn 里**不用绝对坐标**判断控件，只按
「控件类型 + 名字正则 + 相对位置（在输入框的右侧/下方）」匹配。

## 五、为什么还要插件

UIA 轮询有一个天生短板：**它只能"发现空闲"，不能"知道回合结束"**。
应用自己的 Stop 钩子恰好补上这一点——每结束一个回合触发一次，直接返回
`{"decision":"block","reason":"<继续指令>"}` 就能让 agent 接着跑，零轮询开销。

- 插件管「回合级继续」；
- `zburn run` 管「应用崩了 / 无障碍树被关 / 网关挂掉」；
- 两个一起开 = 双保险。
