# 故障排查

先跑一遍自检，90% 的问题它能直接指出来：

```powershell
python zburn.py doctor --config config.json
```

它检查：应用是否有主窗口、无障碍树是否可用、当前是否锁屏、网关是否可访问、额度能否读到、模板是否含非 ASCII。

---

## 一、找不到窗口（`exit 1`）

```
未找到 ZCode 主窗口（进程在跑但没窗口？）
```

- 应用是不是最小化到托盘了？进程在但没有 `MainWindowHandle` —— UIA 也找不到。
- 进程名对不对：`Get-Process | Where-Object MainWindowHandle -ne 0 | Select-Object Name`
- 应用被 `ELECTRON_RUN_AS_NODE` 污染会"启动即退出"，见下面第四条。

## 二、找不到输入框（`exit 2`）

```
未找到输入框：窗口可能还没渲染完，或无障碍树被禁用
```

两种原因：

1. **界面还没渲染完**：脚本已经重试 5 次（每次 800ms）；仍失败就手动
   `pwsh -File scripts/probe-edits.ps1` 看有没有 Edit 控件。
2. **无障碍树被关掉**（锁屏久了最常见）：控件树里只剩 `Intermediate D3D Window`。
   **只能重启应用恢复**，`zburn run` 会自动做这件事。

## 三、投递不完整（`exit 4`）

```
投递不完整 typed=12 target=28
```

字符丢了。按顺序试：

1. 加大间隔：`"uia": {"char_delay_ms": 35}`
2. 应用正在忙（渲染/写日志）时容易丢，把 `feed.interval_seconds` 调大
3. 会话数太多导致 CPU 抢占，减小 `feed.max_sessions`

zburn 的补字逻辑是"只补缺失后缀"，所以丢字不会变成重复文本。

## 四、应用启动即退出（退出码 0 / 9，日志 `bad option: --force-renderer-accessibility`）

被 `ELECTRON_RUN_AS_NODE=1` 污染了。确认并修：

```powershell
Get-ChildItem Env: | Where-Object Name -match 'ELECTRON'
Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
```

配置里的 `app.strip_env` 就是干这个的，保持默认即可。

## 五、输入框里有残留文本（`exit 7`）

```
输入框里有别的内容（57 字），不做追加以免污染
```

**退格被应用忽略了**（实测 WM_CHAR 0x08 / VK_BACK / Ctrl+A 都无效），所以 zburn 不会硬清。
处理方式：

```powershell
pwsh -File scripts/clear-composer.ps1     # 会尝试找"清除"按钮 / 按 Escape，失败会明说
```

实在清不掉：解锁屏幕，手动 Ctrl+A → Delete 一次即可。之后正常跑不会再出现这个问题
（一次成功发送会把输入框清空）。

## 六、点了发送但消息没发出去（`exit 5`）

- 发送按钮识别错了：`zburn.py probe --filter Button` 看真实名字，改 `uia.send_button_regex`
- **特别注意**：`发送` 这个正则也会命中 `移除待发送消息`、`停止生成`。
  zburn 默认用 `busy_regex/queued_regex` 排除它们；如果你改了这些正则，记得保持排除关系，
  否则可能点到"移除待发送消息"（把队列清掉，看起来像发送成功）。

## 七、网关"挂了"，但其实是自己在重启

`gateway.grace_seconds`（默认 60）就是给这种场景的冷静期：探活失败先等一会儿再判定。

**永远不要**让脚本 kill/restart 正在服务的网关——那会让所有对话断流
（表现为 `connection lost mid-reply` / `turn.failed`）。本项目的 `ensure-gateway.ps1`
写死了"只启动、不重启"。

## 八、额度一直不变

- 后端可能要求主动刷新：设 `quota.refresh_url` 和 `refresh_every_seconds`
- 接口要鉴权：`quota.admin_key`（走 `Authorization: Bearer`）
- 字段名不认识：`read_quota` 会自动找 `remaining/remain/balance/left/quota_remaining/surplus`，
  如果后端用别的名字，用 `provider: "command"` 自己解析

## 九、插件钩子不生效

1. 开关文件在不在：`~/.zburn/continue.enabled`（不存在时钩子只写日志）
2. **钩子是在会话启动时绑定的**：装完插件必须**重启会话**（老会话不会触发）
3. 看日志：`~/.zburn/hook.log` 应该每次回合结束都有一行 `Stop 触发`
4. 插件目录结构：

```
<安装目录>/.zcode-plugin/plugin.json
<安装目录>/hooks/hooks.json
<安装目录>/hooks/continue.mjs
```

## 十、`run` 自己在跑，但什么都不做

看 `status.json` 里的 `last_feed_summary`：

| 文案 | 含义 |
|---|---|
| `投喂 0 / 跳过 5` | 5 个会话都在忙或在排队 —— 正常，等下轮 |
| `候选会话 0 个` | `session_regex` 写得太窄，或侧栏没展开 |
| `投喂 0 / 跳过 0 / 失败 6` | 找到了会话但没发成功，看上面第六/三条 |
| `无障碍树不可用` | 见第二条，`run` 会自动重启应用 |

## 十一、日志里反复重启应用

说明无障碍树一直在被关掉。可能原因：屏幕长时间锁定 + 应用被系统休眠。
可以试着：

- 把 `feed.interval_seconds` 调大（减少无声唤醒）
- 关掉系统"锁屏后休眠"或给应用加电源计划例外

## 快速体检命令包

```powershell
python zburn.py doctor --config config.json
python zburn.py probe --filter "Edit|Button"        # 控件树
pwsh -File scripts/probe-edits.ps1                  # 所有输入框及其文本
python zburn.py inject --text "x" --dry-run          # 输入框/按钮定位
python zburn.py feed --dry-run                       # 候选会话列表
python zburn.py status --follow                      # 实时日志
```
